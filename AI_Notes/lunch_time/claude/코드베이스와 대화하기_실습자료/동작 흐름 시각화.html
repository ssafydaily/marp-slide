타일 배송 추적기

방향키를 한 번 누르면, 화면 뒤에서는 택배 시스템과 똑같은 7단계가 순서대로 실행됩니다. 이번 배송 건(오른쪽 이동 한 번)을 예로 들어, 각 단계가 실제로 어느 파일·어느 함수에서 벌어지는지 끝까지 따라가 봅니다.

운송장 번호
MOVE(1) · 오른쪽
배송 트리거
keydown / touchend / click
배송 수단
requestAnimationFrame
총 배송 시간
약 16ms (모니터 1프레임)
  1. STOP 1 / 7

    주문 접수 — 방향키를 누르다

    플레이어가 오른쪽 화살표를 누르는 순간, 접수창구인 keyboard_input_manager.js가 이를 감지합니다. 키코드 39는 미리 정해둔 표(map)를 거쳐 “오른쪽 배송”이라는 뜻으로 번역되고, 접수증 역할을 하는 move 이벤트가 발행됩니다. 스와이프나 화면의 방향 버튼도 같은 접수구로 들어옵니다.

    FILE keyboard_input_manager.js 
    // 39 → 1(오른쪽), 37 → 3(왼쪽) ...
var map = { 38:0, 39:1, 40:2, 37:3 };

document.addEventListener("keydown", function (event) {
  var mapped = map[event.which];
  if (mapped !== undefined) {
    event.preventDefault();
    self.emit("move", mapped);  // 접수 완료
  }
});

    분류 — 어느 쪽부터 처리할지 정하다

    접수된 건은 물류 총괄 game_manager.js의 move()로 넘어갑니다. 게임이 이미 끝났는지 먼저 확인하고, 방향(1=오른쪽)을 좌표 벡터 {x:1, y:0}로 바꾼 뒤, 오른쪽 벽에 가장 가까운 타일부터 처리하도록 순회 순서를 정합니다. 처리 순서가 틀리면 택배가 엉키듯 타일도 뒤섞여 버립니다.

    FILE game_manager.js · move(), buildTraversals()

  if (this.isGameTerminated()) return;
  var vector     = this.getVector(direction);    // {x:1,y:0}
  var traversals = this.buildTraversals(vector); // 오른쪽부터

    이동 & 병합 — 같은 상품은 한 박스로

    정해진 순서대로 각 타일을 판 끝까지 밀어봅니다. 밀리다 만난 타일 값이 같고 이번 배송에서 아직 합쳐진 적이 없다면(!next.mergedFrom), 두 박스를 하나로 합쳐 값을 두 배로 만들고 점수를 올립니다. 단, 한 번의 배송(키 입력)에서 같은 타일은 딱 한 번만 합쳐질 수 있어요 — 그래서 아래 예시처럼 두 개의 4가 만들어져도 그 자리에서 다시 8로 합쳐지진 않습니다.

  4. STOP 4 / 7

    신규 입고 — 빈 창고에 상품 한 개

    이동이 실제로 한 번이라도 일어났다면 addRandomTile()이 호출됩니다. 90% 확률로 “2” 상품, 10% 확률로 “4” 상품 하나가 무작위 빈 칸에 새로 입고됩니다. 이제 넣을 칸도, 합칠 타일도 더 없다면 바로 이 시점에서 “창고 만석 — 게임 오버”가 확정됩니다.

    FILE game_manager.js · addRandomTile() 
    GameManager.prototype.addRandomTile = function () {
  if (this.grid.cellsAvailable()) {
    var value = Math.random() < 0.9 ? 2 : 4;   // 90% : 10%
    var tile  = new Tile(this.grid.randomAvailableCell(), value);
    this.grid.insertTile(tile);
  }
};

    기록 — 현황판과 최고 기록 갱신

    다음 배송을 위해 오늘자 재고 상태를 반드시 남겨둡니다. local_storage_manager.js가 브라우저 저장공간(localStorage)에 판 전체 상태를 JSON으로 적어두고, 이번 점수가 역대 최고 기록보다 높으면 최고 기록도 함께 갈아 끼웁니다. 새로고침해도 게임이 이어지는 이유가 바로 이 단계입니다.

  6. STOP 6 / 7

    하차 — 화면이라는 진열대에 내려놓기

    트럭 기사 역할은 html_actuator.js가 맡습니다. 화면이 다시 그려질 최적의 순간(requestAnimationFrame)을 기다렸다가 진열대(tile-container)를 비우고, grid의 모든 칸을 돌며 타일 하나하나를 실제 <div>로 다시 내려놓습니다. 새로 입고된 상품엔 tile-new, 합쳐진 상품엔 tile-merged 꼬리표를 붙여 다음 단계에서 다르게 등장하도록 표시해둡니다.

    FILE html_actuator.js · actuate(), addTile() 
    window.requestAnimationFrame(function () {
  self.clearContainer(self.tileContainer);      // 진열대 정리
  grid.cells.forEach(function (column) {
    column.forEach(function (cell) {
      if (cell) self.addTile(cell);         // 한 칸씩 내려놓기
    });
  });
});
  7. STOP 7 / 7 · 최종

    수령 확인 — 눈으로 보는 부드러운 이동

    타일은 사실 “이전 위치”에 먼저 살짝 나타난 뒤, 한 프레임 뒤에 클래스 이름만 새 위치(tile-position-x-y)로 바꿔치기됩니다. CSS가 이 위치 변화를 100ms 동안 이어주기(transition) 때문에 우리 눈에는 스르륵 미끄러지는 것처럼 보입니다. 새 타일은 appear로 톡 나타나고, 합쳐진 타일은 pop으로 살짝 튀어올라 “수령 완료”를 알립니다.

    FILE main.scss · .tile transition 
    /* main.scss */
.tile {
  transition: 100ms ease-in-out;
  transition-property: transform;   // 위치 변화 → 슬라이드
}
