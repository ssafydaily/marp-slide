# LangChain Tools 문서 정리 (한글)

LangChain의 "Tools" 문서를 읽었습니다. 내용을 한글로 정리해드릴게요.

## 개요
도구(Tools)는 에이전트가 실시간 데이터 조회, 코드 실행, 외부 DB 쿼리, 실제 행동 수행 등을 할 수 있게 해주는 함수입니다. 채팅 모델이 대화 맥락에 따라 어떤 도구를 언제 호출할지, 어떤 입력값을 줄지 결정합니다.

## 도구 만들기

**기본 정의**: `@tool` 데코레이터를 사용하며, 함수의 docstring이 자동으로 도구 설명이 됩니다. 타입 힌트는 필수이며 입력 스키마를 정의하는 데 사용됩니다. 도구 이름은 `snake_case`를 권장합니다(공백/특수문자는 일부 모델 제공자와 호환성 문제 발생).

**이름/설명 커스터마이징**: `@tool("이름", description="설명")` 형태로 함수명과 다른 이름, 자동 생성된 설명과 다른 설명을 지정할 수 있습니다.

**고급 스키마**: Pydantic 모델이나 JSON 스키마로 복잡한 입력 구조를 정의 가능합니다 (`args_schema` 파라미터 사용).

**예약어**: `config`, `runtime`은 도구 인자 이름으로 사용할 수 없습니다(내부적으로 예약됨). 런타임 정보 접근에는 `ToolRuntime`을 사용해야 합니다.

## 런타임 컨텍스트 접근 (`ToolRuntime`)

도구는 `ToolRuntime` 파라미터를 통해 다음에 접근 가능합니다:

| 구성요소 | 설명 |
|---|---|
| **State** | 단기 기억 — 현재 대화의 메시지, 커스텀 필드 등 |
| **Context** | 실행 시 전달되는 불변 설정값 (사용자 ID, 세션 정보 등) |
| **Store** | 장기 기억 — 대화 간 지속되는 저장소 |
| **Stream Writer** | 도구 실행 중 실시간 업데이트 전송 |
| **Execution Info** | 스레드 ID, 실행 ID, 재시도 횟수 등 |
| **Server Info** | LangGraph Server 실행 시 assistant ID, graph ID, 인증된 사용자 정보 |
| **Config** | 콜백, 태그, 메타데이터 접근용 `RunnableConfig` |
| **Tool Call ID** | 현재 도구 호출의 고유 식별자 |

- **State 접근/수정**: `runtime.state`로 읽고, 상태를 수정하려면 `Command` 객체를 반환합니다. 이때 반드시 `ToolMessage`를 함께 포함시켜야 모델이 결과를 볼 수 있습니다.
- **Context**: `runtime.context`로 접근하며 보통 `thread_id`와 함께 매 호출 시 전달합니다.
- **Store (장기기억)**: `runtime.store`로 네임스페이스/키 패턴으로 데이터 저장·조회 (프로덕션에서는 `InMemoryStore` 대신 `PostgresStore` 등 영구 저장소 권장).
- **Stream Writer**: `runtime.stream_writer`로 진행 상황을 실시간 스트리밍.
- **Execution/Server Info**: 각각 `runtime.execution_info`, `runtime.server_info`로 접근 (일부는 `deepagents>=0.5.0` 필요).

> 참고: 예전 방식인 `InjectedState`, `InjectedStore`, `get_runtime()`, `InjectedToolCallId`는 이제 `ToolRuntime` 하나로 통합되었습니다.

## 도구 실행

**반환값 종류**:
1. **문자열** — 사람이 읽을 수 있는 결과, `ToolMessage`로 변환됨
2. **객체(dict 등)** — 모델이 파싱할 구조화된 결과
3. **멀티모달 콘텐츠** — 텍스트+이미지 등을 표준 콘텐츠 블록으로 반환 가능
4. **`Command`** — 그래프 상태를 갱신할 때 사용 (역시 `ToolMessage` 포함 필요)

**직접 반환 (`return_direct=True`)**: 모델의 추가 처리 없이 도구 출력을 바로 최종 응답으로 사용. 단, 병렬 호출 시 배치 내 *모든* 도구가 `return_direct=True`여야 루프를 종료합니다. 하나라도 아니면 결과를 모델에게 다시 보내 추론하게 합니다.

**오류 처리**: `middleware`(`@wrap_tool_call`)를 사용해 예외를 잡아 `ToolMessage`로 변환하거나 재시도 로직을 구현할 수 있습니다.

## 동적 도구 선택

상황에 따라 사용 가능한 도구 세트를 런타임에 조정하는 방법 두 가지:

1. **사전 등록된 도구 필터링**: 모든 도구를 미리 등록해두고 State/Store/Context(권한, 기능 플래그 등)에 따라 `wrap_model_call` 미들웨어로 노출할 도구를 필터링.
2. **런타임 도구 등록**: MCP 서버 등에서 동적으로 발견/생성되는 도구는 `wrap_model_call`(도구 추가)과 `wrap_tool_call`(실행 처리) 두 훅을 모두 사용해야 함.

## 헤드리스 도구 (Headless Tools)

**서버가 아닌 클라이언트(주로 브라우저)에서 실행되어야 하는 도구**입니다. 이름·설명·인자 스키마는 서버에 등록하지만, 실제 구현은 클라이언트에만 있고 인터럽트/재개 방식으로 실행됩니다.

- **용도**: 위치정보(Geolocation), IndexedDB, 클립보드, Canvas 2D, 파일 선택기 등 브라우저 전용 API, 프라이버시(로컬 저장 유지), 지연시간 감소 등.
- **동작 방식**: 모델이 도구를 호출하면 실행 대신 그래프가 **인터럽트**되고, 앱이 해당 작업을 수행한 뒤 결과와 함께 그래프를 **재개**합니다.
- 일반 도구(서버에서 함수 본문 실행)나 서버사이드 도구 사용(모델 제공자가 원격 실행)과는 다른 개념입니다.

## 사전 제작 도구 & 서버사이드 도구 사용

- LangChain은 웹 검색, 코드 인터프리터, DB 접근 등을 위한 다양한 **사전 제작 도구/툴킷**을 제공합니다.
- 일부 채팅 모델은 **서버사이드 도구**(웹 검색, 코드 인터프리터 등)를 자체적으로 내장하여 모델 제공자 측에서 직접 실행합니다.
