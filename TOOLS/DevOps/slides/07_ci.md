# Step 7. CI – GitHub Actions

## push 할 때마다 자동으로 린트 · 테스트 · 빌드

---

# 학습 목표

- **CI(지속적 통합)** 의 목적을 설명할 수 있다
- GitHub Actions 워크플로 구조(event, job, step)를 이해한다
- **PostgreSQL 서비스 컨테이너**로 CI 에서 실제 DB 테스트를 실행한다
- PR 에 CI 결과를 연결하고 **실패 시 merge 를 막는다**

📁 실습 폴더: `practice/step07_ci/template`

---

# CI 가 없다면?

- "테스트 돌려보셨어요?" "…아뇨"
- 내 PC 에서만 통과 (환경 차이, 커밋 누락 파일)
- 버그가 main 에 들어간 뒤 **한참 후에** 발견

### CI 가 있다면

- push / PR 마다 **깨끗한 환경**에서 자동 검증
- 결과가 PR 화면에 ✅ / ❌ 로 표시
- 실패하면 merge 불가 (Branch protection)

---

# 이번 CI 파이프라인

```
 push / PR (main)
       │
       ▼
┌─────────────┐     ┌──────────────────────────┐     ┌────────────────┐
│ lint        │ ──▶ │ test                     │ ──▶ │ docker-build   │
│ ruff check  │     │ PostgreSQL 서비스 컨테이너 │     │ runtime 이미지  │
│ ruff format │     │ makemigrations --check   │     │ 빌드 검증       │
└─────────────┘     │ pytest --cov             │     └────────────────┘
                    └──────────────────────────┘
```

- `needs` 로 순서 지정 → 앞 단계 실패 시 **뒤 단계 실행 안 함** (빠른 피드백)

# GitHub Actions 구조

```yaml
name: CI                    # 워크플로 이름

on:                         # 언제 실행? (이벤트)
  push:
    branches: [main]

jobs:                       # 무엇을? (작업 묶음, 기본 병렬 실행)
  test:
    runs-on: ubuntu-latest  # 어디서? (러너: GitHub 제공 VM)
    steps:                  # 어떻게? (순서대로 실행)
      - uses: actions/checkout@v4      # 공개 액션 사용
      - run: pytest                    # 셸 명령 실행
```

- 위치: 저장소 루트의 **`.github/workflows/*.yml`**

# 🛠 TODO 2 : lint job

```yaml
jobs:
  lint:
    name: Lint (ruff)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
          cache: pip                              # pip 다운로드 캐시
          cache-dependency-path: requirements-dev.txt

      - name: Install ruff
        run: pip install "ruff>=0.8"

      - name: Lint
        run: ruff check .

      - name: Format check
        run: ruff format --check .
```

# 🛠 TODO 3~4 : test job + PostgreSQL

```yaml
  test:
    name: Test (pytest + PostgreSQL)
    needs: lint
    runs-on: ubuntu-latest

    services:                       # job 동안만 실행되는 컨테이너
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_DB: todo_db
          POSTGRES_USER: todo_user
          POSTGRES_PASSWORD: todo_password
        ports:
          - 5432:5432
        options: >-
          --health-cmd "pg_isready -U todo_user -d todo_db"
          --health-interval 5s
          --health-timeout 3s
          --health-retries 10
```

> `--health-*` 옵션 덕분에 **DB 가 healthy 가 된 후** steps 가 시작됨

# 🛠 TODO 6~8 : 검사 & 테스트 & 리포트

```yaml
      - name: Check migrations
        run: python manage.py makemigrations --check --dry-run

      - name: Run tests
        run: pytest --cov --cov-report=term-missing --cov-report=xml

      - name: Upload coverage report
        uses: actions/upload-artifact@v4
        with:
          name: coverage-report
          path: coverage.xml
```

- `makemigrations --check` : 모델을 바꾸고 **마이그레이션 파일을 빠뜨린 실수** 검출
- `--cov` : `pyproject.toml` 의 `[tool.coverage.run]` 설정 사용
- artifact : Actions 실행 페이지에서 리포트 다운로드 가능

# 🛠 TODO 9 : docker-build job

```yaml
  docker-build:
    name: Docker build
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: docker/setup-buildx-action@v3

      - name: Build image (push 하지 않음)
        uses: docker/build-push-action@v6
        with:
          context: .
          target: runtime
          push: false
          tags: todo-api:ci
          cache-from: type=gha          # GitHub Actions 캐시로 빌드 가속
          cache-to: type=gha,mode=max
```

# 실습 : CI 실행하기

```bash
git switch -c ci/github-actions
git add .github/workflows/ci.yml
git commit -m "ci: add lint, test, docker build workflow"
git push -u origin ci/github-actions
```

1. GitHub 에서 PR 생성
2. PR 하단 **Checks** 영역 확인
3. **Actions** 탭 → 실행 중인 워크플로 클릭 → 각 step 로그 확인

# Branch protection 과 연결

Settings → Branches → main 규칙 편집

- ✅ **Require status checks to pass before merging**
  - `Lint (ruff)`, `Test (pytest + PostgreSQL)`, `Docker build` 추가
- ✅ Require branches to be up to date before merging

```text
 ❌ Some checks were not successful
 Merging is blocked
```

> 이제 **테스트가 깨진 코드는 main 에 들어갈 수 없다**

# 🚑 트러블슈팅

| 증상 | 해결 |
|------|------|
| 워크플로가 실행되지 않음 | 파일 위치(`.github/workflows/`), `on.branches` 이름(main/master) |
| `connection refused` (test) | `services` 의 `ports`, `POSTGRES_HOST: localhost` 확인 |
| `ruff format --check` 실패 | 로컬에서 `ruff format .` 후 커밋 (pre-commit 사용 권장) |
| `No changes detected` 가 아닌 출력 | 마이그레이션 파일 생성 후 커밋 |
| YAML 오류 | 들여쓰기(스페이스 2칸), 탭 사용 금지 |

# 정리

- CI = **통합할 때마다 자동 검증**, 깨끗한 환경에서 같은 절차로
- GitHub Actions : `on` → `jobs` → `steps`
- **서비스 컨테이너**로 CI 에서도 실제 PostgreSQL 사용
- `needs` 로 빠른 실패, Branch protection 으로 **품질 관문** 완성
