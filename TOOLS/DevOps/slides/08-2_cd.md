# Step 8-2. CD – 자동 배포

## main 에 merge 하면 EC2 까지 자동으로

---

# 학습 목표

- CI 성공 후 **자동으로 배포**되는 파이프라인을 만든다
- Docker 이미지를 **GHCR(GitHub Container Registry)** 에 push 한다
- 이미지 **태그 전략**(latest + 커밋 SHA)을 이해한다
- GitHub Secrets 와 SSH 로 서버에 안전하게 배포한다
- 배포 후 **헬스체크**로 성공 여부를 검증한다

📁 실습 폴더: `practice/step08_cd/template`

---

# CD 파이프라인 전체 흐름

```
 PR merge → main
      │
      ▼
 ┌─────────── CI (ci.yml) ───────────┐
 │ lint → test → docker-build        │
 └────────────────┬──────────────────┘
                  │ 성공 시 (workflow_run)
                  ▼
 ┌─────────── CD (cd.yml) ─────────────────────────────────────┐
 │ build-and-push : 이미지 빌드 → ghcr.io/<id>/todo-api:<sha>    │
 │        │                                                    │
 │        ▼                                                    │
 │ deploy : scp 배포파일 → ssh "bash deploy.sh"                 │
 │            └▶ 서버: pull → up -d → migrate → /health/ 확인   │
 └─────────────────────────────────────────────────────────────┘
```

---

# 이미지 레지스트리 : GHCR

- GitHub 이 제공하는 Docker 이미지 저장소 (`ghcr.io`)
- 저장소와 같은 권한 체계, Actions 의 `GITHUB_TOKEN` 으로 **별도 비밀번호 없이** push

### 태그 전략

| 태그 | 예시 | 용도 |
|------|------|------|
| `latest` | `todo-api:latest` | 가장 최근 버전 (편의용) |
| **커밋 SHA** | `todo-api:3f2a9c1...` | **정확히 어떤 코드인지 추적**, 롤백 대상 |

> 배포는 항상 **SHA 태그**로 → "지금 서버에 어떤 코드가 돌고 있나?" 즉시 답변 가능

# 1) GitHub Secrets 등록

저장소 → **Settings → Secrets and variables → Actions → New repository secret**

| Name | 값 |
|------|-----|
| `EC2_HOST` | EC2 퍼블릭 IP (예: `3.35.xxx.xxx`) |
| `EC2_USER` | `ubuntu` |
| `EC2_SSH_KEY` | `deploy_key` 파일 **전체 내용** (BEGIN ~ END 줄 포함) |

<div class="callout info">
<div class="callout-title">Secrets 의 특징</div>
등록 후에는 값을 다시 볼 수 없고, Actions 로그에는 <code>***</code> 로 가려져 출력됩니다.
</div>

# 2) cd.yml : 트리거 (🛠 TODO 1)

```yaml
name: CD

on:
  workflow_run:
    workflows: ["CI"]          # ci.yml 의 name
    types: [completed]
    branches: [main]
  workflow_dispatch:           # Actions 탭에서 수동 실행 가능

concurrency:
  group: deploy-production
  cancel-in-progress: false    # 배포 도중 취소되지 않도록

env:
  # CI 를 통과한 바로 그 커밋으로 배포한다
  DEPLOY_SHA: ${{ github.event.workflow_run.head_sha || github.sha }}
```

- `workflow_run` : **다른 워크플로가 끝났을 때** 실행
- `completed` 는 성공/실패 모두 포함 → 다음 슬라이드에서 성공만 걸러냄

# 3) build-and-push job (🛠 TODO 2)

```yaml
jobs:
  build-and-push:
    # CI 가 실패했다면 배포하지 않는다
    if: github.event_name == 'workflow_dispatch' || github.event.workflow_run.conclusion == 'success'
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write          # GHCR push 권한
    outputs:
      image: ${{ steps.meta.outputs.image }}
```

- `if` : `workflow_run` 은 CI 실패 시에도 실행되므로 **성공일 때만** 진행
- `permissions` : 이 job 에 필요한 최소 권한만 부여

# build-and-push : 로그인 (🛠 TODO 3)

```yaml
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ env.DEPLOY_SHA }}

      - name: 이미지 이름 결정 (GHCR 은 소문자만 허용)
        id: meta
        run: echo "image=ghcr.io/${GITHUB_REPOSITORY_OWNER,,}/todo-api" >> "$GITHUB_OUTPUT"

      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
```

# build-and-push : 빌드 & push (🛠 TODO 4)

```yaml
      - name: Build & Push
        uses: docker/build-push-action@v6
        with:
          context: .
          target: runtime
          push: true
          tags: |
            ${{ steps.meta.outputs.image }}:latest
            ${{ steps.meta.outputs.image }}:${{ env.DEPLOY_SHA }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

- `${GITHUB_REPOSITORY_OWNER,,}` : bash 문법으로 **소문자 변환** (`MyId` → `myid`)
- `outputs.image` : 다음 job(deploy)에 이미지 이름 전달

# 4) deploy job : SSH 준비

```yaml
  deploy:
    needs: build-and-push
    runs-on: ubuntu-latest
    env:
      IMAGE: ${{ needs.build-and-push.outputs.image }}
      SSH_TARGET: ${{ secrets.EC2_USER }}@${{ secrets.EC2_HOST }}
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ env.DEPLOY_SHA }}

      - name: SSH 키 설정
        env:
          EC2_SSH_KEY: ${{ secrets.EC2_SSH_KEY }}
          EC2_HOST: ${{ secrets.EC2_HOST }}
        run: |
          mkdir -p ~/.ssh
          echo "$EC2_SSH_KEY" > ~/.ssh/deploy_key
          chmod 600 ~/.ssh/deploy_key
          ssh-keyscan -H "$EC2_HOST" >> ~/.ssh/known_hosts
```

---

# deploy job : 복사 & 실행 (🛠 TODO 5~6)

```yaml
      - name: 배포 파일 복사
        run: |
          ssh -i ~/.ssh/deploy_key "$SSH_TARGET" "mkdir -p ~/todo-api"
          scp -i ~/.ssh/deploy_key \
            deploy/docker-compose.prod.yml deploy/nginx.conf \
            deploy/deploy.sh deploy/rollback.sh \
            "$SSH_TARGET":~/todo-api/

      - name: 배포 실행
        env:
          GHCR_USER: ${{ github.actor }}
          GHCR_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          ssh -i ~/.ssh/deploy_key "$SSH_TARGET" \
            "cd ~/todo-api && GHCR_USER='$GHCR_USER' GHCR_TOKEN='$GHCR_TOKEN' IMAGE='$IMAGE' IMAGE_TAG='$DEPLOY_SHA' bash deploy.sh"
```

- 배포 설정 파일도 **Git 으로 관리** → 서버에서 직접 수정하지 않음
- `GITHUB_TOKEN` 으로 서버에서 GHCR 로그인 → private 이미지도 pull 가능

# 5) deploy.sh : 서버에서 실행되는 스크립트

```bash
set -euo pipefail                    # 오류 발생 시 즉시 중단
cd "$(dirname "$0")"
COMPOSE="docker compose -f docker-compose.prod.yml"

[ -f .env ] || { echo "[ERROR] .env 파일이 없습니다."; exit 1; }

# 1) GHCR 로그인
echo "$GHCR_TOKEN" | docker login ghcr.io -u "$GHCR_USER" --password-stdin

# 2) 새 이미지 받기 (🛠 TODO 1) — 실패하면 .env 를 바꾸기 전에 중단
export IMAGE IMAGE_TAG
$COMPOSE pull web

# 3) 롤백을 위해 현재 태그를 PREVIOUS_IMAGE_TAG 로 기록한 뒤 새 태그 저장
CURRENT_TAG="$(grep '^IMAGE_TAG=' .env | cut -d= -f2 || true)"
set_env PREVIOUS_IMAGE_TAG "$CURRENT_TAG"
set_env IMAGE_TAG "$IMAGE_TAG"
```

> **pull 이 성공한 뒤에만** `.env` 를 갱신 → 잘못된 태그로 배포해도 기록이 오염되지 않음

---

# deploy.sh : 재기동 & 헬스체크 (🛠 TODO 2~3)

```bash
# 4) 컨테이너 재기동 (마이그레이션은 web 의 entrypoint 가 수행)
$COMPOSE up -d --remove-orphans

# 5) Nginx 를 거쳐 /health/ 가 200 을 반환할 때까지 대기 (최대 90초)
for i in $(seq 1 30); do
    if curl -fsS http://localhost/health/ > /dev/null 2>&1; then
        echo "[OK] 배포 성공: $IMAGE:$IMAGE_TAG"
        docker image prune -f > /dev/null      # 안 쓰는 이미지 정리
        exit 0
    fi
    echo "[WAIT] 헬스체크 대기 중... ($i/30)"
    sleep 3
done

echo "[ERROR] 헬스체크 실패. 이전 버전으로 되돌리기: bash rollback.sh"
exit 1                                         # → Actions 의 deploy job 실패
```

# GHCR 패키지 확인

GitHub 프로필 → **Packages → todo-api**

```text
todo-api
  latest  3f2a9c1d8e...   Published 5 minutes ago
          a81b20f4c3...   Published 2 hours ago
          ...
```

- 커밋마다 이미지가 쌓임 → **어떤 버전으로든 되돌릴 수 있음**
- (선택) 패키지 설정에서 Visibility 를 Public 으로 바꾸면 로그인 없이 pull 가능

# 🚑 트러블슈팅

| 증상 | 해결 |
|------|------|
| CD 가 실행되지 않음 | `workflows: ["CI"]` 이름 일치, cd.yml 이 **main 에 있어야** 동작 |
| `denied: permission_denied` (push) | `permissions: packages: write` 확인 |
| `Permission denied (publickey)` | `EC2_SSH_KEY` 전체 복사, 서버 `authorized_keys` 확인 |
| `ssh: connect ... timed out` | 보안그룹 22 포트 소스 확인 |
| `.env 파일이 없습니다` | 서버 `~/todo-api/.env` 생성 (8-1) |
| 헬스체크 실패 / 400 Bad Request | `DJANGO_ALLOWED_HOSTS` 에 `localhost` 와 EC2 IP 포함 |
| `manifest unknown` | 이미지 이름 소문자, `.env` 의 `IMAGE` 값 확인 |

# 정리

- **CD** = 검증된 코드를 사람 손 없이 운영까지
- 이미지는 **SHA 태그**로 버전 관리 → 추적 · 롤백 가능
- 비밀값 : GitHub Secrets(배포용) / 서버 `.env`(실행용)
- 배포 후 **헬스체크**로 성공을 확인해야 진짜 배포 완료
