# 데이터 모델

현실 세계의 정보를 컴퓨터에 표현하기 위해 단순화·추상화한 모형.

| 구성 요소 | 설명 |
| --- | --- |
| 구조 (Structure) | 개체 타입과 그들 사이의 관계. 데이터 구조 |
| 연산 (Operation) | 데이터를 처리하는 작업에 대한 명세 |
| 제약 조건 (Constraint) | 저장될 수 있는 데이터의 논리적 제약 |

| 종류 | 설명 | 산출물 |
| --- | --- | --- |
| 개념적 데이터 모델 | 현실 세계를 추상적 개념으로 표현 | E-R 모델 |
| 논리적 데이터 모델 | 컴퓨터가 이해할 수 있는 구조로 표현 | 관계 모델, 계층 모델, 망 모델 |
| 물리적 데이터 모델 | 실제 저장 구조 | 테이블, 인덱스 정의 |

# E-R 모델

피터 첸(P. Chen)이 제안한 개념적 데이터 모델. 개체, 속성, 관계로 표현한다.

| 기호 | 의미 |
| --- | --- |
| 사각형 | 개체 타입 (Entity) |
| 마름모 | 관계 타입 (Relationship) |
| 타원 | 속성 (Attribute) |
| 밑줄 친 타원 | 기본키 속성 |
| 이중 타원 | 다중값 속성 |
| 이중 사각형 | 약한 개체 타입 |
| 선 | 개체와 속성, 개체와 관계를 연결 |

- 관계의 대응 수: 1:1, 1:N, N:M

---

# 실습 스키마의 관계

| 관계 | 대응 | 구현 |
| --- | --- | --- |
| 학과 – 학생 | 1 : N | 학생.학과코드 (외래키) |
| 학과 – 과목 | 1 : N | 과목.학과코드 (외래키) |
| 학생 – 과목 | N : M | **수강** 테이블 (교차 테이블) |
| 부서 – 사원 | 1 : N | 사원.부서번호 (외래키) |
| 사원 – 사원 | 1 : N (순환) | 사원.상사사번 (자기 참조) |

- 1 : N 관계는 N 쪽 테이블에 외래키를 둔다
- N : M 관계는 양쪽 기본키를 외래키로 갖는 별도 테이블로 풀어낸다
- 수강의 기본키 {학번, 과목코드} 는 두 외래키의 조합이다

# 정규화가 필요한 이유 — 이상 현상

모든 정보를 한 테이블에 담은 `수강기록` 을 생각해 보자. 기본키는 {학번, 과목코드}.

| 학번 | 이름 | 학과코드 | 학과명 | 과목코드 | 과목명 | 점수 |
| --- | --- | --- | --- | --- | --- | --- |
| 1001 | 김철수 | D01 | 컴퓨터공학과 | C101 | 데이터베이스 | 85 |
| 1001 | 김철수 | D01 | 컴퓨터공학과 | C102 | 자료구조 | 90 |
| 1002 | 이영희 | D01 | 컴퓨터공학과 | C101 | 데이터베이스 | 92 |
| 1002 | 이영희 | D01 | 컴퓨터공학과 | C105 | 운영체제 | 78 |
| 1003 | 박민수 | D02 | 전자공학과 | C103 | 회로이론 | 88 |

- 같은 정보(이름, 학과명, 과목명)가 여러 행에 **중복**된다
- 중복 때문에 삽입·삭제·갱신 시 생기는 문제를 **이상(Anomaly)** 이라고 한다

---

# 이상 현상 세 가지

| 이상 | 설명 | `수강기록` 의 사례 |
| --- | --- | --- |
| 삽입 이상 | 원하지 않는 값도 함께 넣어야 삽입할 수 있다 | 수강 내역이 없는 학생 강하늘을 넣을 수 없다 (과목코드가 기본키라 NULL 불가) |
| 삭제 이상 | 삭제할 때 다른 정보까지 연쇄적으로 사라진다 | 정우성의 유일한 수강 내역을 지우면 정우성이라는 학생 정보도 사라진다 |
| 갱신 이상 | 일부만 수정되어 정보가 모순된다 | 학과명을 한 행만 바꾸면 D01 의 이름이 두 가지가 된다 |

- 정규화의 목적: **중복을 줄여 이상 현상을 방지**하는 것
- 정규화는 논리적 설계 단계에서 수행한다

---

# 함수적 종속

X 값이 정해지면 Y 값이 하나로 결정될 때 **Y 는 X 에 함수적으로 종속**된다고 하고 `X → Y` 로 쓴다. X 를 결정자, Y 를 종속자라고 한다.

`수강기록` 의 함수적 종속

```
학번               → 이름, 학과코드
학과코드           → 학과명
과목코드           → 과목명
{학번, 과목코드}   → 점수
```

| 종속 | 설명 | 예 |
| --- | --- | --- |
| 완전 함수적 종속 | 기본키 **전체**에 종속 | {학번, 과목코드} → 점수 |
| 부분 함수적 종속 | 기본키의 **일부**에 종속 | 학번 → 이름 |
| 이행적 함수적 종속 | A → B, B → C 일 때 A → C | 학번 → 학과코드 → 학과명 |

# 정규화 과정

| 단계 | 조건 |
| --- | --- |
| 비정규 릴레이션 | |
| ↓ **도**메인이 원자값 | 1NF |
| ↓ **부**분 함수적 종속 제거 | 2NF |
| ↓ **이**행적 함수적 종속 제거 | 3NF |
| ↓ **결**정자이면서 후보키가 아닌 것 제거 | BCNF |
| ↓ **다**치 종속 제거 | 4NF |
| ↓ **조**인 종속성 이용 | 5NF |

- 앞 글자를 따서 **도 → 부 → 이 → 결 → 다 → 조**
- 각 정규형은 앞 단계의 조건을 모두 만족해야 한다
- 정규화는 릴레이션을 **무손실 분해**한다. 분해한 릴레이션을 조인하면 원래대로 복원된다

---

# 1NF — 원자값

모든 속성의 도메인이 원자값으로만 되어 있다.

| 학번 | 이름 | 수강과목 |
| --- | --- | --- |
| 1001 | 김철수 | C101, C102 |
| 1002 | 이영희 | C101, C105 |

한 칸에 값이 여러 개 들어 있으므로 1NF 가 아니다. 행을 나누어 원자값으로 만든다.

| 학번 | 이름 | 과목코드 |
| --- | --- | --- |
| 1001 | 김철수 | C101 |
| 1001 | 김철수 | C102 |
| 1002 | 이영희 | C101 |
| 1002 | 이영희 | C105 |

---

# 2NF — 부분 함수적 종속 제거

기본키가 아닌 모든 속성이 기본키에 **완전 함수적 종속**이다.

`수강기록` 은 기본키 {학번, 과목코드} 의 일부에만 종속된 속성이 있다.

```
학번     → 이름, 학과코드, 학과명     (부분 종속)
과목코드 → 과목명                     (부분 종속)
```

부분 종속을 떼어 내어 분해한다.

```
학생(학번, 이름, 학과코드, 학과명)
과목(과목코드, 과목명)
수강(학번, 과목코드, 점수)
```

- 기본키가 단일 속성이면 부분 종속이 있을 수 없으므로 1NF 이면 곧 2NF 다

---

# 3NF — 이행적 함수적 종속 제거

기본키가 아닌 모든 속성이 기본키에 **이행적으로 종속되지 않는다**.

```
학생(학번, 이름, 학과코드, 학과명)
학번 → 학과코드,  학과코드 → 학과명     ∴ 학번 → 학과명 (이행 종속)
```

이행 종속을 떼어 낸다.

```
학생(학번, 이름, 학과코드)
학과(학과코드, 학과명)
```

- 최종 결과가 실습 스키마의 학생, 학과, 과목, 수강이다
- 판별 요령: 기본키가 아닌 속성이 **다른 일반 속성을 결정**하면 3NF 위반

---

# BCNF — 결정자는 모두 후보키

모든 결정자가 후보키다.

수강지도(학번, 과목, 교수). 한 교수는 한 과목만 맡고, 한 과목은 여러 교수가 맡을 수 있다.

```
{학번, 과목} → 교수
교수 → 과목            ← 교수는 결정자이지만 후보키가 아니다
```

| 학번 | 과목 | 교수 |
| --- | --- | --- |
| 1001 | 데이터베이스 | 김교수 |
| 1002 | 데이터베이스 | 이교수 |
| 1003 | 데이터베이스 | 김교수 |

- 3NF 는 만족하지만 BCNF 는 아니다. `교수 → 과목` 을 분리한다

```
지도(학번, 교수)     교수과목(교수, 과목)
```

---

# 4NF · 5NF

| 정규형 | 조건 |
| --- | --- |
| 4NF | 다치 종속(MVD) `A ↠ B` 가 있을 때 릴레이션의 모든 속성이 A 에 함수적 종속 |
| 5NF | 모든 조인 종속이 후보키를 통해서만 성립 |

다치 종속의 예: 개발자(이름, 언어, 자격증). 언어와 자격증은 서로 무관하다.

| 이름 | 언어 | 자격증 |
| --- | --- | --- |
| 홍길동 | Java | 정보처리기사 |
| 홍길동 | Java | SQLD |
| 홍길동 | Python | 정보처리기사 |
| 홍길동 | Python | SQLD |

- `이름 ↠ 언어`, `이름 ↠ 자격증`. (이름, 언어)와 (이름, 자격증)으로 분해한다

# 반정규화 (Denormalization)

정규화된 모델을 **성능 향상과 운영 편의**를 위해 의도적으로 통합·중복·분리하는 것.

| 방법 | 설명 |
| --- | --- |
| 테이블 통합 | 자주 조인하는 테이블을 하나로 합친다 |
| 테이블 분할 | 수평 분할(행 기준), 수직 분할(컬럼 기준) |
| 중복 테이블 추가 | 집계 테이블, 진행 테이블 등을 따로 둔다 |
| 중복 속성 추가 | 조인을 줄이기 위해 다른 테이블의 컬럼을 복사해 둔다 |

- 조회 성능은 좋아지지만 데이터의 **일관성과 무결성이 떨어질 수 있다**
- 정규화의 반대 작업이라 "역정규화", "비정규화" 라고도 한다

# 정리 — 서술형 답안 키워드

| 질문 | 답 |
| --- | --- |
| 이상 현상 세 가지 | 삽입 이상, 삭제 이상, 갱신 이상 |
| 1NF 조건 | 도메인이 원자값 |
| 2NF 로 가려면 | 부분 함수적 종속 제거 |
| 3NF 로 가려면 | 이행적 함수적 종속 제거 |
| BCNF 로 가려면 | 결정자이면서 후보키가 아닌 것 제거 |
| 4NF / 5NF | 다치 종속 제거 / 조인 종속성 이용 |
| A → B, B → C 일 때 A → C | 이행적 함수적 종속 |
| 성능을 위해 중복·통합·분리 | 반정규화 |
| E-R 기호: 사각형 / 마름모 / 타원 | 개체 / 관계 / 속성 |
