# 5단계. 집계와 그룹

집계 함수 · GROUP BY · HAVING · ROLLUP · 윈도우 함수

- 집계 함수가 NULL을 다루는 방식을 안다
- WHERE 와 HAVING 을 구분한다
- 순위 함수 세 가지의 결과 차이를 안다

> 실습지: `labs/lab05_집계.md`

---

# 집계 함수

| 함수 | 의미 | NULL |
| --- | --- | --- |
| `COUNT(*)` | 행 수 | **포함** |
| `COUNT(컬럼)` | 값이 있는 행 수 | 제외 |
| `COUNT(DISTINCT 컬럼)` | 서로 다른 값의 수 | 제외 |
| `SUM`, `AVG` | 합계, 평균 | 제외 |
| `MAX`, `MIN` | 최댓값, 최솟값 | 제외 |

- `COUNT(*)` 만 NULL을 센다. 나머지는 모두 NULL을 건너뛴다
- 분산 `VARIANCE`, 표준편차 `STDDEV` 도 집계 함수다

---

# 집계 함수와 NULL

```sql
SELECT COUNT(*), COUNT(점수), SUM(점수), AVG(점수) FROM 수강;
```

| COUNT(*) | COUNT(점수) | SUM(점수) | AVG(점수) |
| --- | --- | --- | --- |
| 14 | 12 | 960 | 80.0000 |

- `AVG(점수)` = 960 ÷ **12** = 80. 전체 행 수 14로 나누지 않는다

```sql
SELECT AVG(보너스), AVG(IFNULL(보너스, 0)) FROM 사원;
-- 333.3333 (2000 ÷ 6)     166.6667 (2000 ÷ 12)
```

- NULL을 0으로 바꾸면 분모가 달라져 평균이 달라진다

# GROUP BY

```sql
SELECT 과목코드, COUNT(*) AS 인원, COUNT(점수) AS 채점, AVG(점수) AS 평균
FROM 수강
GROUP BY 과목코드;
```

| 과목코드 | 인원 | 채점 | 평균 |
| --- | --- | --- | --- |
| C101 | 4 | 3 | 87.3333 |
| C102 | 3 | 3 | 75.6667 |
| C103 | 3 | 3 | 79.3333 |
| C104 | 2 | 2 | 77.5000 |
| C105 | 2 | 1 | 78.0000 |

- 수강생이 없는 C106은 수강 테이블에 행이 없으므로 결과에 나오지 않는다

---

# GROUP BY 규칙

SELECT 절에는 **GROUP BY 에 쓴 컬럼**과 **집계 함수**만 올 수 있다.

```sql
SELECT 이름, 부서번호, AVG(급여) FROM 사원 GROUP BY 부서번호;
```

```
ERROR 1055 (42000): Expression #1 of SELECT list is not in GROUP BY clause
and contains nonaggregated column 'study.사원.이름' ...
```

- 한 부서에 이름이 여러 개인데 한 행으로 줄여야 하니 어떤 이름을 보여 줄지 정할 수 없다
- `ONLY_FULL_GROUP_BY` 를 끈 MySQL은 이 쿼리를 실행해 버린다 (0단계 참고)

---

# GROUP BY 와 NULL

```sql
SELECT 부서번호, COUNT(*) AS 인원, SUM(급여) AS 합계 FROM 사원 GROUP BY 부서번호;
```

| 부서번호 | 인원 | 합계 |
| --- | --- | --- |
| NULL | 1 | 2800 |
| 10 | 3 | 20200 |
| 20 | 4 | 19900 |
| 30 | 3 | 15500 |
| 40 | 1 | 5200 |

- 그룹 기준 컬럼이 NULL인 행은 **NULL끼리 하나의 그룹**이 된다
- 그룹 수를 묻는 문제에서 NULL 그룹을 빠뜨리지 않는다

---

# HAVING — 그룹에 대한 조건

```sql
SELECT 과목코드, COUNT(*) AS 인원
FROM 수강
GROUP BY 과목코드
HAVING COUNT(*) >= 3;        -- C101(4), C102(3), C103(3)
```

| | WHERE | HAVING |
| --- | --- | --- |
| 대상 | 행 | 그룹 |
| 시점 | 그룹을 만들기 전 | 그룹을 만든 후 |
| 집계 함수 | 사용 불가 | 사용 가능 |

```sql
SELECT 과목코드 FROM 수강 WHERE COUNT(*) >= 3 GROUP BY 과목코드;   -- 오류
```

---

# WHERE 와 HAVING 을 함께

```sql
SELECT 부서번호, AVG(급여) AS 평균
FROM 사원
WHERE 직급 <> '사장'          -- 1. 사장을 먼저 제외하고
GROUP BY 부서번호             -- 2. 부서별로 묶은 뒤
HAVING AVG(급여) >= 5000      -- 3. 평균 5000 이상인 부서만
ORDER BY 평균 DESC;
```

| 부서번호 | 평균 |
| --- | --- |
| 10 | 5600.0000 |
| 40 | 5200.0000 |
| 30 | 5166.6667 |

- 사장(9000)을 빼서 10번 부서 평균이 6733 → 5600 으로 내려갔다
- 20번(4975)과 NULL 그룹(2800)은 HAVING 에서 걸러졌다

# ROLLUP — 소계와 총계

```sql
SELECT 부서번호, 직급, SUM(급여) AS 합계 FROM 사원
WHERE 부서번호 IN (10, 20)
GROUP BY 부서번호, 직급 WITH ROLLUP;
```

| 부서번호 | 직급 | 합계 | |
| --- | --- | --- | --- |
| 10 | 대리·부장·사장 | 4200 / 7000 / 9000 | 상세 3행 |
| 10 | NULL | 20200 | 10번 소계 |
| 20 | 과장·대리·부장·사원 | 5500 / 4200 / 7200 / 3000 | 상세 4행 |
| 20 | NULL | 19900 | 20번 소계 |
| NULL | NULL | 40100 | 총계 |

결과는 7 + 2 + 1 = **10행**이다.

# 그룹 함수 — ROLLUP · CUBE · GROUPING SETS

| 함수 | 만들어 내는 집계 | 컬럼 N개일 때 |
| --- | --- | --- |
| `ROLLUP(a, b)` | (a, b), (a), 전체 | N + 1 레벨 |
| `CUBE(a, b)` | (a, b), (a), (b), 전체 | 2ᴺ 조합 |
| `GROUPING SETS(a, b)` | (a), (b) | 지정한 것만 |

- ROLLUP 은 **컬럼 순서가 결과에 영향**을 준다. `ROLLUP(a, b)` ≠ `ROLLUP(b, a)`
- CUBE 는 모든 조합이므로 순서와 무관하다

| | 표준·Oracle | MySQL 8.4 |
| --- | --- | --- |
| ROLLUP | `GROUP BY ROLLUP(a, b)` | `GROUP BY a, b WITH ROLLUP` |
| CUBE, GROUPING SETS | 지원 | **미지원** |

# 윈도우 함수

행을 줄이지 않고 **각 행에 집계·순위 결과를 붙인다**.

```sql
함수() OVER ([PARTITION BY 그룹 기준] [ORDER BY 정렬 기준])
```

| 분류 | 함수 |
| --- | --- |
| 순위 | `RANK`, `DENSE_RANK`, `ROW_NUMBER` |
| 집계 | `SUM`, `AVG`, `COUNT`, `MAX`, `MIN` |
| 행 순서 | `FIRST_VALUE`, `LAST_VALUE`, `LAG`, `LEAD` |
| 그룹 내 비율 | `PERCENT_RANK`, `CUME_DIST`, `NTILE`, `RATIO_TO_REPORT` |

- GROUP BY 는 그룹당 1행으로 줄이고, PARTITION BY 는 행 수를 유지한다
- `LAG` 는 이전 행, `LEAD` 는 다음 행의 값을 가져온다

---

# 순위 함수 세 가지

```sql
SELECT 이름, 급여,
       RANK()       OVER (ORDER BY 급여 DESC) AS rk,
       DENSE_RANK() OVER (ORDER BY 급여 DESC) AS drk,
       ROW_NUMBER() OVER (ORDER BY 급여 DESC) AS rn
FROM 사원 WHERE 급여 <= 5500;
```

| 이름 | 급여 | RANK | DENSE_RANK | ROW_NUMBER |
| --- | --- | --- | --- | --- |
| 정코딩 | 5500 | 1 | 1 | 1 |
| 윤판매 | 5500 | 1 | 1 | 2 |
| 조인사 | 5200 | **3** | **2** | 3 |
| 한서버 | 4200 | 4 | 3 | 4 |
| 문기획 | 4200 | 4 | 3 | 5 |
| 강매출 | 3200 | **6** | **4** | 6 |

---

# 순위 함수 정리

| 함수 | 동점 처리 | 다음 순위 | 예 |
| --- | --- | --- | --- |
| `RANK` | 같은 순위 | 건너뜀 | 1, 1, 3, 4, 4, 6 |
| `DENSE_RANK` | 같은 순위 | 건너뛰지 않음 | 1, 1, 2, 3, 3, 4 |
| `ROW_NUMBER` | 다른 순위 | 연속 번호 | 1, 2, 3, 4, 5, 6 |

- `ROW_NUMBER` 에서 동점인 행끼리의 순서는 정해져 있지 않다

```sql
RANK() OVER (PARTITION BY 부서번호 ORDER BY 급여 DESC)   -- 부서 안에서의 순위
SUM(급여) OVER (PARTITION BY 부서번호)                   -- 각 행에 부서 합계
SUM(급여) OVER (ORDER BY 사번)                           -- 누적 합계
```

# 표준 SQL 과 MySQL 차이

| 항목 | 표준·시험 | MySQL |
| --- | --- | --- |
| HAVING 에서 SELECT 별칭 | 사용 불가 | 사용 가능 (확장) |
| GROUP BY 에 없는 컬럼 SELECT | 오류 | `ONLY_FULL_GROUP_BY` 가 꺼져 있으면 실행됨 |
| CUBE, GROUPING SETS | 지원 | 미지원 |
| `RATIO_TO_REPORT` | Oracle 지원 | 미지원 |

```sql
-- MySQL에서는 실행되지만 시험 답안으로는 쓰지 않는다
SELECT 과목코드, AVG(점수) AS 평균 FROM 수강 GROUP BY 과목코드 HAVING 평균 >= 79;

-- 답안은 이렇게
SELECT 과목코드, AVG(점수) AS 평균 FROM 수강 GROUP BY 과목코드 HAVING AVG(점수) >= 79;
```

# 정리 — 자주 틀리는 것

1. `COUNT(*)` 만 NULL을 센다
2. `AVG` 는 NULL을 뺀 건수로 나눈다
3. 집계 조건은 HAVING, 행 조건은 WHERE
4. SELECT 에는 GROUP BY 컬럼과 집계 함수만
5. NULL도 하나의 그룹이 된다
6. ROLLUP 결과 행 수 = 상세 + 소계 + 총계 1
7. `RANK` 는 순위를 건너뛰고 `DENSE_RANK` 는 건너뛰지 않는다
8. 행이 없는 그룹은 결과에 나오지 않는다 (0으로 나오게 하려면 OUTER JOIN, 6단계)
