# 7단계. 서브쿼리

스칼라 · 인라인 뷰 · 중첩 · 상관 서브쿼리 / IN · EXISTS · ANY · ALL

- 서브쿼리의 위치와 반환 형태에 따른 종류를 구분한다
- `NOT IN` 과 NULL의 함정을 안다
- ANY 와 ALL 을 MIN, MAX 로 바꿔 읽는다

> 실습지: `labs/lab07_서브쿼리.md`

---

# 서브쿼리의 종류

| 위치 | 이름 | 반환 |
| --- | --- | --- |
| SELECT 절 | 스칼라 서브쿼리 | 1행 1열 |
| FROM 절 | 인라인 뷰 | 테이블 |
| WHERE·HAVING 절 | 중첩 서브쿼리 | 단일 행 또는 다중 행 |

| 반환 형태 | 쓸 수 있는 연산자 |
| --- | --- |
| 단일 행 | `=`, `<>`, `<`, `>`, `<=`, `>=` |
| 다중 행 | `IN`, `ANY`, `ALL`, `EXISTS` |
| 다중 컬럼 | `(a, b) IN (SELECT x, y ...)` |

- 서브쿼리는 괄호로 감싼다
- 메인 쿼리의 컬럼을 참조하면 **상관 서브쿼리**, 아니면 비상관 서브쿼리

---

# 단일 행 서브쿼리

```sql
SELECT 이름, 급여 FROM 사원
WHERE 급여 > (SELECT AVG(급여) FROM 사원);     -- 평균 5300
```

| 이름 | 급여 |
| --- | --- |
| 김대표 | 9000 |
| 박개발 | 7200 |
| 이기획 | 7000 |
| 최영업 | 6800 |
| 정코딩 | 5500 |
| 윤판매 | 5500 |

- WHERE 절에는 집계 함수를 직접 쓸 수 없으므로 서브쿼리로 먼저 값을 구한다
- 비교 연산자 뒤의 서브쿼리가 2행 이상을 반환하면 오류다

---

# IN — 다중 행 서브쿼리

```sql
-- 데이터베이스(C101)를 수강하는 학생
SELECT 이름 FROM 학생
WHERE 학번 IN (SELECT 학번 FROM 수강 WHERE 과목코드 = 'C101');
-- 김철수, 이영희, 박민수, 오세훈
```

```sql
-- 부서별 최고 급여자 (다중 컬럼)
SELECT 이름, 급여 FROM 사원
WHERE (부서번호, 급여) IN (SELECT 부서번호, MAX(급여) FROM 사원 GROUP BY 부서번호);
-- 김대표, 박개발, 최영업, 조인사
```

- 두 번째 쿼리에서 부서번호가 NULL인 신수습은 나오지 않는다
- `(NULL, 2800) IN ((NULL, 2800), ...)` 은 NULL 비교가 섞여 TRUE 가 되지 못한다

---

# 함정 — NOT IN 과 NULL

부하 직원이 없는 사원(누구의 상사도 아닌 사원)을 찾으려 한다.

```sql
SELECT 이름 FROM 사원
WHERE 사번 NOT IN (SELECT 상사사번 FROM 사원);       -- 0행
```

서브쿼리 결과에 NULL(김대표의 상사사번)이 있기 때문이다.

```
사번 NOT IN (101, 102, NULL)
= 사번 <> 101 AND 사번 <> 102 AND 사번 <> NULL
=    TRUE     AND    TRUE     AND  UNKNOWN      →  UNKNOWN
```

- `NOT IN` 의 목록에 NULL이 하나라도 있으면 **결과는 항상 0행**
- `IN` 은 OR 로 풀리므로 NULL이 있어도 일치하는 값이 있으면 TRUE

---

# NOT IN 함정을 피하는 방법

```sql
-- 방법 1: 서브쿼리에서 NULL 제거
SELECT 이름 FROM 사원
WHERE 사번 NOT IN (SELECT 상사사번 FROM 사원 WHERE 상사사번 IS NOT NULL);

-- 방법 2: NOT EXISTS
SELECT 이름 FROM 사원 e
WHERE NOT EXISTS (SELECT 1 FROM 사원 x WHERE x.상사사번 = e.사번);
```

두 쿼리 모두 한서버, 오신입, 강매출, 조인사, 문기획, 신수습 6행을 반환한다.

- `NOT EXISTS` 는 행이 있는지만 보므로 NULL의 영향을 받지 않는다

---

# EXISTS

서브쿼리 결과가 **한 행이라도 있으면 TRUE**. 대부분 상관 서브쿼리와 함께 쓴다.

```sql
-- 급여 7000 이상인 사원이 있는 부서
SELECT 부서명 FROM 부서 d
WHERE EXISTS (SELECT * FROM 사원 e
              WHERE e.부서번호 = d.부서번호 AND e.급여 >= 7000);
-- 기획부, 개발부
```

- 서브쿼리의 SELECT 목록은 의미가 없다. `SELECT *`, `SELECT 1` 어느 것이든 같다
- 메인 쿼리의 행마다 서브쿼리를 평가한다고 생각하고 읽는다

---

# ANY 와 ALL

30번 부서의 급여: 6800, 5500, 3200

| 조건 | 의미 | 같은 표현 |
| --- | --- | --- |
| `> ALL (서브쿼리)` | 모든 값보다 크다 | `> MAX` → 6800 초과 |
| `< ALL (서브쿼리)` | 모든 값보다 작다 | `< MIN` → 3200 미만 |
| `> ANY (서브쿼리)` | 어느 하나보다 크다 | `> MIN` → 3200 초과 |
| `< ANY (서브쿼리)` | 어느 하나보다 작다 | `< MAX` → 6800 미만 |
| `= ANY (서브쿼리)` | 어느 하나와 같다 | `IN` |

```sql
SELECT 이름, 급여 FROM 사원
WHERE 급여 > ALL (SELECT 급여 FROM 사원 WHERE 부서번호 = 30);
-- 이기획 7000, 박개발 7200, 김대표 9000
```

- `SOME` 은 `ANY` 와 같다

---

# ANY · ALL 과 빈 결과, NULL

| 서브쿼리 결과 | `> ALL` | `> ANY` |
| --- | --- | --- |
| 0행 (연구소의 급여) | 항상 TRUE → 12행 | 항상 FALSE → 0행 |
| NULL 포함 (보너스 전체) | 0행 | 비교 가능한 값으로만 판정 |

```sql
SELECT COUNT(*) FROM 사원 WHERE 급여 > ALL (SELECT 급여 FROM 사원 WHERE 부서번호 = 50);  -- 12
SELECT COUNT(*) FROM 사원 WHERE 급여 > ANY (SELECT 급여 FROM 사원 WHERE 부서번호 = 50);  -- 0
SELECT COUNT(*) FROM 사원 WHERE 급여 > ALL (SELECT 보너스 FROM 사원);                    -- 0
```

- `> ALL` 을 `> MAX` 로 바꿔 쓰면 빈 결과에서 동작이 달라진다 (MAX 는 NULL을 반환)

---

# 상관 서브쿼리

메인 쿼리의 컬럼을 서브쿼리가 참조한다.

```sql
-- 자기 부서의 평균 급여보다 많이 받는 사원
SELECT 이름, 부서번호, 급여 FROM 사원 e
WHERE 급여 > (SELECT AVG(급여) FROM 사원 WHERE 부서번호 = e.부서번호);
```

| 이름 | 부서번호 | 급여 | 부서 평균 |
| --- | --- | --- | --- |
| 김대표, 이기획 | 10 | 9000, 7000 | 6733 |
| 박개발, 정코딩 | 20 | 7200, 5500 | 4975 |
| 최영업, 윤판매 | 30 | 6800, 5500 | 5167 |

- 40번 부서의 조인사는 혼자라 평균과 같으므로 `>` 를 만족하지 못한다
- 신수습은 `부서번호 = NULL` 이 되어 서브쿼리가 NULL을 반환하므로 제외된다

# 스칼라 서브쿼리와 인라인 뷰

```sql
-- 스칼라 서브쿼리: SELECT 절, 반드시 1행 1열
SELECT 학번, 이름,
       (SELECT COUNT(*) FROM 수강 e WHERE e.학번 = s.학번) AS 과목수
FROM 학생 s WHERE 학년 = 1;
-- 김철수 2, 한소희 1, 강하늘 0
```

```sql
-- 인라인 뷰: FROM 절, 별칭 필수
SELECT d.부서명, t.평균급여
FROM 부서 d
JOIN (SELECT 부서번호, AVG(급여) AS 평균급여 FROM 사원 GROUP BY 부서번호) t
  ON d.부서번호 = t.부서번호
WHERE t.평균급여 >= 5200;
-- 기획부 6733.3333, 인사부 5200.0000
```

- 스칼라 서브쿼리는 짝이 없으면 NULL을 반환한다. 위에서는 `COUNT` 라서 0이 나왔다

# DML 에서의 서브쿼리

```sql
UPDATE 사원 SET 급여 = 급여 + 100
WHERE 부서번호 = (SELECT 부서번호 FROM 부서 WHERE 부서명 = '영업부');

DELETE FROM 수강
WHERE 학번 IN (SELECT 학번 FROM 학생 WHERE 학과코드 = 'D02');

INSERT INTO 학생_백업 SELECT 학번, 이름 FROM 학생 WHERE 학년 = 4;
```

MySQL 전용 제약: 수정 대상 테이블을 같은 문장의 서브쿼리에서 바로 읽을 수 없다.

```sql
UPDATE 사원 SET 급여 = 급여 + 100 WHERE 급여 < (SELECT AVG(급여) FROM 사원);
-- ERROR 1093: You can't specify target table '사원' for update in FROM clause
```

- 표준 SQL과 Oracle 에서는 정상 실행된다. 시험 답안으로는 문제없는 쿼리다

---

# 같은 문제, 여러 풀이

"수강 내역이 없는 학생" 을 구하는 네 가지 방법

```sql
-- 1. NOT IN (수강.학번은 NOT NULL 이라 안전)
SELECT 이름 FROM 학생 WHERE 학번 NOT IN (SELECT 학번 FROM 수강);
-- 2. NOT EXISTS
SELECT 이름 FROM 학생 s WHERE NOT EXISTS (SELECT 1 FROM 수강 e WHERE e.학번 = s.학번);
-- 3. OUTER JOIN + IS NULL
SELECT s.이름 FROM 학생 s LEFT JOIN 수강 e ON s.학번 = e.학번 WHERE e.학번 IS NULL;
-- 4. 차집합
SELECT 학번 FROM 학생 EXCEPT SELECT 학번 FROM 수강;
```

- 빈칸 채우기 문제에서는 어느 형태로든 나올 수 있다. 서로 바꿔 쓸 수 있어야 한다

---

# 정리 — 자주 틀리는 것

1. `NOT IN` 의 서브쿼리 결과에 NULL이 있으면 0행
2. 비교 연산자 뒤 서브쿼리는 1행만 반환해야 한다
3. `> ALL` 은 최댓값보다, `> ANY` 는 최솟값보다 큰 것
4. `EXISTS` 는 값이 아니라 행의 존재 여부만 본다
5. 인라인 뷰에는 별칭을 붙인다
6. 스칼라 서브쿼리는 1행 1열만 반환해야 한다
7. 상관 서브쿼리는 메인 쿼리의 행마다 값을 대입해서 읽는다
8. 다중 컬럼 `IN` 도 NULL이 섞이면 일치하지 않는다
