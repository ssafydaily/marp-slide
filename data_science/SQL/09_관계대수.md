# 관계 대수와 관계 해석

| | 관계 대수 | 관계 해석 |
| --- | --- | --- |
| 성격 | **절차적** 언어 | **비절차적** 언어 |
| 기술 내용 | 원하는 정보를 **어떻게** 유도하는가 (연산 순서) | 원하는 정보가 **무엇**인가 |
| 기반 | 연산자와 연산 규칙 | 술어 해석 (Predicate Calculus) |
| 종류 | 순수 관계 연산자, 일반 집합 연산자 | 튜플 관계 해석, 도메인 관계 해석 |

- 둘 다 관계 데이터베이스를 처리하는 기능과 능력 면에서 **동등**하다
- 관계 해석은 코드(E. F. Codd)가 제안했다
- SQL 은 관계 대수와 관계 해석을 기초로 한 고급 언어다

# 연산자 한눈에 보기

| 분류 | 연산자 | 기호 | 의미 |
| --- | --- | --- | --- |
| 순수 관계 | Select | σ (시그마) | 조건에 맞는 **튜플** 선택 |
| | Project | π (파이) | 지정한 **속성** 추출 |
| | Join | ⋈ | 공통 속성으로 두 릴레이션 결합 |
| | Division | ÷ | 상대 릴레이션의 모든 값과 관련된 튜플 |
| 일반 집합 | 합집합 | ∪ | |
| | 교집합 | ∩ | |
| | 차집합 | − | |
| | 카티션 곱 | × | 모든 튜플 조합 |

- Select 는 **수평 연산**(행), Project 는 **수직 연산**(열)

# Select (σ)

조건을 만족하는 튜플의 부분 집합을 구한다.

```
σ 학년≥3 (학생)
```

```sql
SELECT * FROM 학생 WHERE 학년 >= 3;
```

| 학번 | 이름 | 학년 | 학과코드 | 주소 |
| --- | --- | --- | --- | --- |
| 1003 | 박민수 | 3 | D02 | 서울 |
| 1005 | 정우성 | 4 | D03 | 서울 |
| 1007 | 오세훈 | 3 | D01 | 광주 |
| 1009 | 김철수 | 4 | D02 | 인천 |

- 차수는 그대로(5), 카디널리티는 줄어든다(10 → 4)
- 관계 대수의 Select 는 SQL 의 **WHERE** 에 해당한다. SQL 의 SELECT 절이 아니다

---

# Project (π)

지정한 속성만 추출한다. 결과에서 **중복 튜플은 제거**된다.

```
π 주소 (학생)
```

```sql
SELECT DISTINCT 주소 FROM 학생;
```

- 학생은 10명이지만 결과는 6행이다 (서울, 부산, 대전, 광주, 인천, NULL)
- 관계 대수의 결과는 릴레이션이므로 중복이 없다. SQL 로 옮길 때 `DISTINCT` 가 필요하다

두 연산의 조합

```
π 이름, 학년 ( σ 학과코드='D01' (학생) )
```

```sql
SELECT DISTINCT 이름, 학년 FROM 학생 WHERE 학과코드 = 'D01';
```

# Join (⋈)

| 조인 | 기호 | 설명 |
| --- | --- | --- |
| 세타 조인 | R ⋈(AθB) S | 비교 연산자(=, ≠, <, ≤, >, ≥)로 결합 |
| 동등 조인 | R ⋈(A=B) S | θ 가 `=` 인 조인. 공통 속성이 중복되어 나온다 |
| 자연 조인 | R ⋈ S | 동등 조인에서 **중복 속성을 제거** |
| 외부 조인 | ⟕ ⟖ ⟗ | 짝 없는 튜플도 NULL 로 채워 포함 |
| 세미 조인 | ⋉ ⋊ | 조인에 참여하는 한쪽 릴레이션의 튜플만 |

```
π 이름, 학과명 ( 학생 ⋈ 학과 )
```

```sql
SELECT DISTINCT 이름, 학과명 FROM 학생 NATURAL JOIN 학과;
```

- 학생(차수 5) ⋈ 학과(차수 3) 의 자연 조인 결과 차수는 5 + 3 − 1 = **7**

---

# Division (÷)

`R ÷ S` : S 의 **모든** 튜플과 관련이 있는 R 의 튜플에서 S 의 속성을 뺀 것.

"C101 과 C105 를 **모두** 수강한 학생의 학번"

```
π 학번, 과목코드 (수강)  ÷  {C101, C105}
```

| 학번 | 수강 과목 | C101 | C105 | 결과 |
| --- | --- | --- | --- | --- |
| 1001 | C101, C102 | O | X | |
| 1002 | C101, C105 | O | O | **포함** |
| 1003 | C101, C103 | O | X | |
| 1007 | C101, C105 | O | O | **포함** |

- 결과: {1002, 1007}
- "모든 ~ 을 ~ 한" 이라는 표현이 나오면 디비전이다

---

# Division 을 SQL 로

SQL 에는 디비전 연산자가 없다. 두 가지 방법으로 표현한다.

```sql
-- 방법 1: 개수 세기
SELECT 학번 FROM 수강
WHERE 과목코드 IN ('C101', 'C105')
GROUP BY 학번
HAVING COUNT(*) = 2;
```

```sql
-- 방법 2: 이중 NOT EXISTS ("수강하지 않은 대상 과목이 존재하지 않는 학생")
SELECT DISTINCT e.학번 FROM 수강 e
WHERE NOT EXISTS (
    SELECT 1 FROM 과목 c
    WHERE c.과목코드 IN ('C101', 'C105')
      AND NOT EXISTS (SELECT 1 FROM 수강 x
                      WHERE x.학번 = e.학번 AND x.과목코드 = c.과목코드));
```

두 쿼리 모두 1002, 1007 을 반환한다.

# 일반 집합 연산자

합집합, 교집합, 차집합은 두 릴레이션이 **합병 가능**해야 한다 (차수가 같고 대응 속성의 도메인이 같다).

| 연산 | 차수 | 카디널리티 |
| --- | --- | --- |
| R ∪ S | 같음 | \|R ∪ S\| ≤ \|R\| + \|S\| |
| R ∩ S | 같음 | \|R ∩ S\| ≤ MIN(\|R\|, \|S\|) |
| R − S | 같음 | \|R − S\| ≤ \|R\| |
| R × S | R 의 차수 **+** S 의 차수 | \|R\| **×** \|S\| |

카티션 곱 예: 학생(차수 5, 카디널리티 10) × 과목(차수 4, 카디널리티 6)

- 차수 5 + 4 = **9**, 카디널리티 10 × 6 = **60**
- 차수는 더하고 카디널리티는 곱한다

# 관계 대수와 SQL 대응

| 관계 대수 | SQL |
| --- | --- |
| σ 조건 (R) | `SELECT * FROM R WHERE 조건` |
| π 속성 (R) | `SELECT DISTINCT 속성 FROM R` |
| R ⋈ S | `R NATURAL JOIN S`, `R JOIN S ON ...` |
| R ∪ S | `UNION` |
| R ∩ S | `INTERSECT` |
| R − S | `EXCEPT` (`MINUS`) |
| R × S | `CROSS JOIN`, `FROM R, S` |
| R ÷ S | `NOT EXISTS` 이중 사용, 또는 `GROUP BY ~ HAVING COUNT` |

# 관계 대수식 읽기

```
π 이름 ( σ 과목명='데이터베이스' ( 학생 ⋈ 수강 ⋈ 과목 ) )
```

안쪽부터 읽는다.

1. 학생, 수강, 과목을 자연 조인한다
2. 과목명이 '데이터베이스' 인 튜플만 고른다
3. 이름 속성만 추출한다

```sql
SELECT DISTINCT s.이름
FROM 학생 s
JOIN 수강 e ON s.학번 = e.학번
JOIN 과목 c ON e.과목코드 = c.과목코드
WHERE c.과목명 = '데이터베이스';
-- 김철수, 이영희, 박민수, 오세훈
```

- 여기서는 학생과 과목에 `학과코드` 가 공통으로 있어 실제 `NATURAL JOIN` 은 의도와 다르게 동작한다. SQL 에서는 `ON` 으로 조인 조건을 명시한다

# 관계 해석

원하는 정보가 **무엇인지**만 정의한다. 수학의 술어 해석에 기반한다.

| 구분 | 기호 | 의미 |
| --- | --- | --- |
| 연산자 | ∨ | OR |
| | ∧ | AND |
| | ¬ | NOT |
| 정량자 | ∀ | 전칭 정량자. "모든" (for **A**ll) |
| | ∃ | 존재 정량자. "어떤", "존재한다" (there **E**xists) |

튜플 관계 해석의 예: 3학년 이상 학생의 이름

```
{ t.이름 | 학생(t) ∧ t.학년 ≥ 3 }
```

- 튜플 관계 해석은 튜플 변수를, 도메인 관계 해석은 도메인 변수를 쓴다

# 질의 최적화의 기본 규칙

같은 결과를 내는 관계 대수식이 여러 개일 때, 중간 결과를 작게 만드는 쪽이 유리하다.

1. **Select 를 가능한 한 일찍** 수행해 튜플 수를 줄인다
2. **Project 를 가능한 한 일찍** 수행해 속성 수를 줄인다
3. **Join 은 가능한 한 늦게** 수행한다. 조인 전에 양쪽을 먼저 줄인다
4. 카티션 곱 뒤의 Select 는 조인으로 바꾼다

```
(나쁨)  σ 학년=1 ( 학생 ⋈ 수강 )           10행과 14행을 조인한 뒤 거른다
(좋음)  ( σ 학년=1 (학생) ) ⋈ 수강          3행으로 줄인 뒤 조인한다
```

- DBMS 의 옵티마이저가 이런 변환을 자동으로 수행한다. 결과는 `EXPLAIN` 으로 볼 수 있다
