# Lab 02. 데이터 모델링과 정규화

슬라이드: `02_모델링_정규화.md`

정규화된 실습 스키마를 거꾸로 합쳐 비정규 테이블을 만들고, 이상 현상을 직접 일으켜 본다. `CREATE TABLE ... AS SELECT` 와 조인은 3단계와 6단계에서 다루므로 지금은 그대로 따라 실행한다.

## 1. 따라 하기

### 1-1. 비정규 테이블 만들기

```sql
CREATE TABLE 수강기록 AS
SELECT s.학번, s.이름, s.학과코드, d.학과명, e.과목코드, c.과목명, e.점수
FROM 학생 s
JOIN 수강 e ON s.학번 = e.학번
JOIN 과목 c ON e.과목코드 = c.과목코드
LEFT JOIN 학과 d ON s.학과코드 = d.학과코드;

ALTER TABLE 수강기록 ADD PRIMARY KEY (학번, 과목코드);

SELECT * FROM 수강기록 WHERE 학번 IN (1001, 1002, 1003);
```

| 학번 | 이름 | 학과코드 | 학과명 | 과목코드 | 과목명 | 점수 |
| --- | --- | --- | --- | --- | --- | --- |
| 1001 | 김철수 | D01 | 컴퓨터공학과 | C101 | 데이터베이스 | 85 |
| 1001 | 김철수 | D01 | 컴퓨터공학과 | C102 | 자료구조 | 90 |
| 1002 | 이영희 | D01 | 컴퓨터공학과 | C101 | 데이터베이스 | 92 |
| 1002 | 이영희 | D01 | 컴퓨터공학과 | C105 | 운영체제 | 78 |
| 1003 | 박민수 | D02 | 전자공학과 | C101 | 데이터베이스 | NULL |
| 1003 | 박민수 | D02 | 전자공학과 | C103 | 회로이론 | 88 |

이름, 학과명, 과목명이 여러 행에 반복된다.

### 1-2. 삽입 이상

수강 내역이 아직 없는 학생 강하늘을 넣어 본다.

```sql
INSERT INTO 수강기록 (학번, 이름, 학과코드, 학과명) VALUES (1010, '강하늘', 'D03', '경영학과');
-- ERROR 1364 (HY000): Field '과목코드' doesn't have a default value
```

과목코드가 기본키의 일부라 NULL 이 될 수 없다. 학생 정보만 따로 넣을 방법이 없다.

### 1-3. 갱신 이상

학과명을 한 행만 바꾼다.

```sql
UPDATE 수강기록 SET 학과명 = '컴퓨터학부' WHERE 학번 = 1001 AND 과목코드 = 'C101';

SELECT DISTINCT 학과코드, 학과명 FROM 수강기록 WHERE 학과코드 = 'D01';
```

| 학과코드 | 학과명 |
| --- | --- |
| D01 | 컴퓨터학부 |
| D01 | 컴퓨터공학과 |

같은 학과코드에 학과명이 두 개가 되었다. 어느 쪽이 맞는지 알 수 없다.

### 1-4. 삭제 이상

정우성(1005)은 회계원리 한 과목만 수강한다. 이 수강 내역을 취소한다.

```sql
DELETE FROM 수강기록 WHERE 학번 = 1005;

SELECT COUNT(*) FROM 수강기록 WHERE 이름 = '정우성';   -- 0
```

수강 내역만 지우려 했는데 정우성이라는 학생이 있었다는 정보까지 사라졌다.

### 1-5. 함수적 종속 확인

`X → Y` 가 성립하면 X 값 하나에 Y 값은 하나뿐이다. 데이터를 초기 상태로 다시 만든 뒤 확인한다.

```sql
DROP TABLE 수강기록;
-- 1-1 의 CREATE TABLE ... AS SELECT 와 ALTER TABLE 을 다시 실행한다

-- 학번 → 이름 : 학번마다 이름이 1개인가
SELECT 학번, COUNT(DISTINCT 이름) AS 이름수 FROM 수강기록 GROUP BY 학번 HAVING COUNT(DISTINCT 이름) > 1;
-- 0행 (위반 없음)

-- 이름 → 학번 : 이름마다 학번이 1개인가
SELECT 이름, COUNT(DISTINCT 학번) AS 학번수 FROM 수강기록 GROUP BY 이름 HAVING COUNT(DISTINCT 학번) > 1;
-- 김철수 2 (위반. 이름은 학번을 결정하지 못한다)
```

### 1-6. 무손실 분해 확인

정규화된 네 테이블을 조인하면 `수강기록` 과 같은 행 수가 나온다.

```sql
SELECT COUNT(*) FROM 수강기록;   -- 14

SELECT COUNT(*)
FROM 학생 s
JOIN 수강 e ON s.학번 = e.학번
JOIN 과목 c ON e.과목코드 = c.과목코드
LEFT JOIN 학과 d ON s.학과코드 = d.학과코드;   -- 14
```

### 1-7. 정리

```sql
DROP TABLE 수강기록;
```

## 2. 확인 문제

**Q1.** 다음 릴레이션은 몇 정규형까지 만족하는가? 기본키는 {주문번호, 상품코드} 이다.

```
주문상세(주문번호, 상품코드, 수량, 상품명, 단가)

함수적 종속:
  {주문번호, 상품코드} → 수량
  상품코드 → 상품명, 단가
```

**Q2.** Q1 의 릴레이션을 한 단계 높은 정규형으로 분해하시오.

**Q3.** 다음 릴레이션은 몇 정규형까지 만족하는가? 기본키는 사번이다.

```
사원정보(사번, 이름, 부서번호, 부서명, 지역)

함수적 종속:
  사번 → 이름, 부서번호
  부서번호 → 부서명, 지역
```

**Q4.** Q3 의 릴레이션에서 제거해야 할 종속의 이름을 쓰고, 분해 결과를 쓰시오.

**Q5.** 다음 설명에 해당하는 이상 현상의 이름을 각각 쓰시오.

1. 한 튜플을 삭제할 때 의도하지 않은 다른 정보까지 함께 삭제된다.
2. 데이터를 삽입할 때 원하지 않는 값도 함께 입력해야 한다.
3. 튜플의 속성 값을 일부만 수정해 정보에 모순이 생긴다.

**Q6.** 정규화 과정에서 다음 작업이 이루어지는 단계를 "○NF → ○NF" 형식으로 쓰시오.

1. 이행적 함수적 종속 제거
2. 결정자이면서 후보키가 아닌 것 제거
3. 다치 종속 제거

**Q7.** 정규화된 엔터티, 속성, 관계를 시스템의 성능 향상과 개발 운영의 단순화를 위해 중복, 통합, 분리하는 데이터 모델링 기법을 무엇이라 하는가?

**Q8.** E-R 다이어그램에서 다음 기호가 의미하는 것을 쓰시오.

1. 사각형
2. 마름모
3. 타원
4. 이중 타원

**Q9.** 실습 스키마의 `사원` 테이블은 3NF 를 만족하는가? 직급에 따라 급여가 정해진다는 규칙이 있다면 어떻게 달라지는가?

<summary>정답과 해설</summary>

- **Q1.** 1NF. 상품명과 단가가 기본키의 일부인 상품코드에만 종속된다(부분 함수적 종속). 2NF 를 만족하지 못한다.
- **Q2.** `주문상세(주문번호, 상품코드, 수량)`, `상품(상품코드, 상품명, 단가)`
- **Q3.** 2NF. 기본키가 단일 속성이라 부분 종속은 없지만, 사번 → 부서번호 → 부서명 의 이행 종속이 있다.
- **Q4.** 이행적 함수적 종속. `사원(사번, 이름, 부서번호)`, `부서(부서번호, 부서명, 지역)`
- **Q5.** 1. 삭제 이상, 2. 삽입 이상, 3. 갱신 이상
- **Q6.** 1. 2NF → 3NF, 2. 3NF → BCNF, 3. BCNF → 4NF
- **Q7.** 반정규화 (Denormalization)
- **Q8.** 1. 개체 타입, 2. 관계 타입, 3. 속성, 4. 다중값 속성
- **Q9.** 현재 정의로는 사번이 모든 속성을 직접 결정하므로 3NF 를 만족한다. `직급 → 급여` 규칙이 있다면 사번 → 직급 → 급여 의 이행 종속이 생겨 3NF 위반이 되고, `직급급여(직급, 급여)` 를 분리해야 한다. 정규형은 데이터가 아니라 업무 규칙(함수적 종속)으로 판단한다.
